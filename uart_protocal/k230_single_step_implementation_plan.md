# K230 UART 单步执行实施计划

## 目标

K230 每次只通过 UART7 下发一个机械动作。STM32 不缓存整套拼图流程，
每个动作完成后返回带相同 `sequence` 的状态，K230 收到终态后才能发送下一步。

## 本次动作范围

| 动作 | 参数 | 执行语义 |
| --- | --- | --- |
| X | `x_mm` | X 轴绝对坐标，Y 保持不变 |
| Y | `y_mm` | Y 轴绝对坐标，X 保持不变 |
| 旋转 | `angle_deg` | 末端相对旋转，顺时针为正 |
| 电磁铁 | `0/1` | `0` 释放，`1` 吸附 |
| Z | `0/1` | `0` 上，`1` 下 |

坐标沿用当前机械坐标系：上电软件零点位于左上角，X 向右为正，
Y 向下为正；X 范围 `0~181 mm`，Y 范围 `0~305 mm`。

## 交互约束

1. K230 使用递增的 8 位 `sequence`，自然允许从 `255` 回绕到 `0`。
2. STM32 接收有效动作后返回 `BUSY`。
3. 机械动作到位或动作等待时间结束后返回 `DONE`。
4. 参数非法、硬件未就绪、执行忙或超时时返回 `ERROR + error_code`。
5. 相同序号和相同内容重发时不重复动作，只重发当前或最近的状态。
6. 当前动作未结束时，不接受其他序号的新动作。

## 实现步骤

1. 固定单步命令和状态 payload。
2. 在 UART7 接收任务中加入命令队列和状态发送队列。
3. 新增单步执行器，调用现有 XY、C610 旋转、PWM Z 轴和电磁铁接口。
4. 添加 RX/TX、队列溢出、动作完成和错误 watch 计数。
5. 更新 K230 对接协议，编译并记录结果。

## 验证判据

- Makefile 构建通过。
- `g_k230_uart_stats.rx_bytes`、`step_frames` 能区分物理接收和有效单步帧。
- `tx_frames`、`tx_bytes` 能证明 STM32 实际发送了状态帧。
- `g_k230_step_status` 能直接观察当前序号、动作、完成数和错误。
- X/Y 只有实际到达容差范围后才回 `DONE`。
- 旋转只有观察到 C610 动作开始并结束后才回 `DONE`。

## 实验结果

- 2026-07-31：完成 UART7 `0x10` 单步命令接收和 `0x90` 状态返回。
- 命令队列深度为 4，状态队列深度为 8；状态帧由 UART 任务轮询发送，
  不会阻塞 1 kHz 电机控制任务。
- 新增 `g_k230_uart_stats` 的单步 RX、队列溢出、TX 帧/字节/错误计数。
- 新增 `g_k230_step_status`，ELF 地址为 `0x20008120`；地址仅对应本次构建，
  后续固件结构变化后必须重新从同一 ELF 取地址。
- 本次 ELF 中 `g_k230_uart_stats=0x2000837c`，`g_k230_target=0x200083b8`。
- `git diff --check` 通过，相关源文件和文档均少于 500 行。
- Makefile `-j8` 构建通过，无编译错误；产物为 `build/DM02_Lite.elf/.hex/.bin`。
- 固件大小：text `100644`，data `756`，bss `35104` bytes。
- 未烧录、未连接 K230 实测；物理 RX/TX、CRC、动作完成状态仍需上板验证。
